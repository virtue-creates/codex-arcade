# Communication Policy

このプロジェクトの主な人間ユーザーは日本語で考え、判断する。

そのため、プロジェクト運用ドキュメントは日本語主軸で書く。

## 言語方針

## 人間が読むdocs

日本語主軸にする。

対象例:

- 方針メモ
- 本部判断
- ロードマップ
- 体験設計
- マーケ/クリエイティブ統合メモ
- 会社運営メモ

## コードと構造データ

英語のままでよい。

対象例:

- `id`
- `status`
- `games.json`
- `game.json`
- ファイル名
- JavaScript変数
- CSSクラス

## 公開UI

日本語主軸 + アーケード用語は英語でよい。

例:

- CREDITS
- INSERT COIN
- PLAY
- CABINET
- COMING SOON

## エージェント向け指示

日本語主軸でよい。

ただし、出力フォーマットやJSON構造など、機械的に扱う部分は英語キーを使ってよい。

## 部署エージェントの姿勢

部署エージェントは、単に本部や人間の意見に同意するだけでは足りない。

各部署は必ず以下を分けて出す。

```txt
Human-originated
= 人間が出した方向性

Agent-drafted
= その部署が出した叩き台や独自視点

Co-developed
= 人間とAIのブレストで修正・発展した視点

Risks / Concerns
= 懸念、弱点、反対意見

Alternatives
= 別案

Tradeoffs
= 採用する場合に捨てるもの、弱くなるもの

Recommendation
= その部署としての推奨
```

## 本部の姿勢

本部は、部署から返ってきた案をそのまま褒めて丸めない。

本部は以下を明確にする。

- 何が人間由来のアイデアか
- 何が部署から追加された視点か
- 何が人間とAIのブレストで育った視点か
- 何を採用するか
- 何を保留するか
- 何を却下するか
- どんなリスクがあるか

## 目的

この方針の目的は、Codex Arcade社を「ただ同意するAIの集まり」にしないこと。

部署ごとの視点差、緊張関係、判断の履歴を残すことで、AIエージェント会社としての学習価値を高める。

## Human-Agent Collaboration

詳しくは `docs/human-agent-collaboration.md` を参照する。

このプロジェクトでは、AIエージェントの出力は最終回答ではなく、ブレストの材料として扱う。

エージェント出力は自動的に決定事項にならない。

本部と人間が確認し、必要なら修正し、採用・保留・却下を決める。
