# Human-Agent Collaboration

このプロジェクトでは、AIエージェントの出力は最終回答ではなく、ブレストの材料として扱う。

現時点のCodex Arcade社の本質は、全自動ではなく、人間とAI部署の共創である。

## 基本認識

Codex Arcadeは「AIが勝手に全部決める」プロジェクトではない。

少なくとも当面は、以下の流れが基本になる。

```txt
1. 人間が違和感や方向性を出す
2. エージェントが案を出す
3. 人間がその案を見て、違和感や追加意見を出す
4. 本部が整理する
5. 必要ならdocsに反映する
6. 次の実装や検証に進む
```

これを、人間とAIエージェントの共同編集ループとして扱う。

## 人間の役割

人間は以下を担う。

- 違和感
- 好み
- ニュアンス
- 方向性
- 何を面白いと感じるか
- 公開してよいかの判断
- 最終的な世界観の判断

AIがそれらを完全に代替する前提にはしない。

## AI部署の役割

AI部署は以下を担う。

- 専門視点の叩き台
- 懸念
- 反対意見
- 別案
- 比較
- 実装案
- QA
- ドキュメント化

AI部署は同意役ではない。

## エージェント出力の扱い

エージェントの出力は、以下のどれかとして扱う。

```txt
Draft
= 叩き台

Input
= 本部判断の材料

Challenge
= 現在方針への反論や懸念

Decision
= 本部と人間が承認したもの
```

エージェント出力は、自動的にDecisionにはならない。

## 同調しすぎを防ぐ

AIエージェントは、前提を与えると同調的にまとまりやすい。

そのため、部署エージェントには以下を求める。

- 同意だけで終わらない
- 現在案の弱点を出す
- 反対意見を出す
- 別案を出す
- 何が人間由来で、何が自分の追加視点かを分ける
- 「採用するなら何を捨てることになるか」を書く

## 本部の役割

本部は、部署案をそのまま採用しない。

本部は以下を分ける。

```txt
Human-originated
= 人間が出した問題意識や方向性

Agent-drafted
= エージェントが出した叩き台

Co-developed
= 人間とAIの対話で修正された案

HQ decision
= 本部として採用・保留・却下した判断
```

## 今回の学び

MVPシェルのリデザインでは、Marketing AgentとCreative Agentの出力が同じ方向にまとまりやすかった。

その後、人間が以下を指摘した。

- 出力が同調的に見える
- 本部が「筋がいい」と言うと、人間が出した方向性までエージェント案のように見える
- 実際には、人間が違和感を出し、それを元にAIとブレストして修正している

このため、今後は「エージェントが加えた視点」と「人間とのブレストで育った視点」を明確に分ける。

## 自動化との関係

将来的に自動化を強める場合でも、この共同編集ループは残る可能性が高い。

自動化の目的は、人間を判断から外すことではなく、以下を軽くすること。

- 案を出す
- 比較する
- リスクを見つける
- docsに残す
- 実装に落とす
- QAする
- レポートする

人間は引き続き、違和感、好み、方向性、公開判断を持つ。
