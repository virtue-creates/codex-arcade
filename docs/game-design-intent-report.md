# Game Design Intent Report

このテンプレートは、ゲームチャットが本部へ返す「ゲーム性の意図レポート」。

目的は、完成報告を単なる「動きました」にしないこと。

本部と人間QAは、このレポートを見てから実際に遊び、以下を判断する。

- 開発者が狙った楽しさは伝わっているか
- 人間が感じた楽しさ/分かりづらさと、開発意図がズレていないか
- 改善すべき点がバグなのか、説明不足なのか、ゲーム設計そのものなのか

## いつ提出するか

ゲームチャットは、以下のタイミングで提出する。

1. MVP実装完了時
2. 大きなゲーム性変更の前
3. QA後の改善版を出す時

## 提出フォーマット

```md
# Game Design Intent Report: [Game Title]

## 1. このゲームは何をするゲームか

プレイヤーが1プレイ中に何を見て、何を操作し、何を目指すゲームなのか。

## 2. プレイヤーにとって何が楽しい想定か

例:
- 反射神経が気持ちいい
- ルートを考えるのが楽しい
- うまく誘導できた時に気持ちいい
- スコア更新を狙いたくなる
- 見た目や演出を触っているだけで楽しい

## 3. どこで悩ませるゲームか

プレイヤーに選択や判断がある場合、何を迷わせたいのか。

例:
- どの区間を先に直すか
- どの敵を避けるか倒すか
- どのピンをどこに置くか

## 4. どこで気持ちよくさせるゲームか

成功した瞬間、連鎖した瞬間、スコアが伸びた瞬間など、体験の山場。

## 5. 初見プレイヤーに何が伝われば成功か

最初の30秒で分かってほしいこと。

## 6. 今回のMVPで意図的に捨てたもの

時間やスコープの都合で入れていない要素。

## 7. 現時点で開発者が不安に思っていること

遊び方が伝わるか、単調すぎないか、難しすぎないか、操作が分かるか、など。

## 8. 人間QAに特に見てほしいこと

本部や人間プレイヤーに確認してほしいポイント。
```

## 本部での使い方

本部は、提出された意図レポートと人間QAの感想を照合する。

照合の見方:

- 意図どおり伝わっていて楽しい: 磨き込みへ進む
- 意図は分かるが伝わっていない: UI/説明/演出を改善する
- 意図自体が弱い: ゲーム性を再設計する
- 想定外に別の楽しさがある: 方向転換を検討する

このレポートは、将来の自動QAやエージェント分業でも使う。
