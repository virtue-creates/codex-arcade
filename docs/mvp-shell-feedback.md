# MVP Shell Feedback

This document records human feedback on the first Codex Arcade MVP shell.

## Context

Current project position:

```txt
Phase 1 Sprint 2/3 - Arcade MVP Implementation
```

The first parent site shell exists, but it should be treated as an early working prototype, not a finished direction.

## Human Feedback Summary

## First Impression

The current shell does not yet feel like an online arcade.

It has some working structure, but the emotional impression is not there yet.

## Language Direction

Recommended direction:

```txt
Japanese as the main explanatory language
English for arcade UI terms where it feels natural
```

Examples of terms that may stay in English:

- CREDITS
- INSERT COIN
- PLAY
- CABINET
- COMING SOON

## Public Surface Direction

The public-facing site should prioritize the arcade feeling.

The internal AI-agent company model remains important, but it should not dominate the first user-facing screen.

Do not lead with:

- Phase / Sprint labels
- Development process language
- AI company explanation

These can live in docs, devlog, about pages, or behind-the-scenes content.

## Arcade Feeling

The current shell does not yet create enough arcade excitement.

The desired direction is not a literal copy of old Japanese arcades, but the project should learn from feelings like:

- choosing a cabinet
- putting in 100 yen / one credit
- sitting down for one play
- seeing a machine wake up
- selecting a game in a physical-feeling arcade space

This should be used as inspiration, not as a strict visual requirement.

## Cabinet Presentation

Three cabinets visible at once is acceptable.

However, the current "card" feeling is too generic. It should move toward a cabinet-selection feeling rather than a SaaS card grid.

## Concept Cabinets

Showing Cabinet 02 and Cabinet 03 as coming soon is acceptable and desirable.

## Credit Display

The idea of credits is good, but the current display does not yet create a strong arcade feeling.

Credit display should support the feeling of "one play" rather than just being a decorative number.

## Current Board Display

Do not show Phase / Sprint / Current Board on the public arcade surface.

Development progress belongs in docs and headquarters workflow, not the first user-facing arcade UI.

## Priority For Next Iteration

Focus next on:

- Arcade feeling
- Insert coin / one-play experience
- Japanese-first copy
- Visual direction
- Cabinet presentation

## Important Guardrail

Do not jump directly to implementation based on one fixed idea.

Marketing and Creative should first brainstorm options and propose directions.
